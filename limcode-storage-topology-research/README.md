历史可用性恢复后，继续交付 A 的查询、跨项目刷新/分页、执行归属和内容增长治理。B（项目分库）与 D（共享服务）保留明确进入条件，A 全部完成不是它们的前置关卡。

## 复现实验注意事项

原始脚本保留了 `/tmp/limcode-topology-research-6pLhQV` 等研究环境路径，也可能引用未归档的隔离仓库、依赖、数据库快照或上游克隆。因此，归档保存了实验方法与结果，**不是可以直接原地执行的完整实验环境**。

如需复跑，应先新建隔离研究目录、准备匹配的源码与依赖，并调整脚本中的路径。不要把写入型实验指向正在使用的业务数据根。读取运行数据库时仍需通过只读连接和 SQLite Backup API 建立一致性副本；不要直接复制活动 SQLite/WAL 文件。
